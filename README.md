# 矩形板材下料 · 多订单拼版断头切割排料（Panel Nesting）

面向小型手作工坊的矩形板材裁切排样 Web 应用，支持**多张订单混合拼版**：
每张订单填写唯一订单号与零件清单（不同订单允许同名零件），系统按
**订单 → 零件行 → 数量的固定输入顺序**、遵循**断头切割（guillotine cut）**规则
逐板生成裁切方案，落位保留订单归属，并按订单输出跨板取件清单与材料费分摊。
表单还可登记若干**临时余板库存**（带唯一编号与实际长宽）：已开板放不下时先按输入顺序
启用尚未使用、且能加工的余板，最后才开标准新板；余板不计材料费。
发现损坏件时，可在分单取件清单中勾选后一键生成**独立补切方案**
（仅重排所选件，补切只开标准新板、不耗用余板，原方案落位与分摊不变）。
需要评估订单变动时，可选择一张订单生成**撤单影响预览**：以生成方案时的
输入快照分别计算撤单前后两套排料，对比新增标准板数、已用余板编号、
材料费总额与每张保留订单的分摊增减，原方案与表单保持不变。
每次生成方案后，系统还会自动给出**可回收余料清单**：从每张板最终的空闲矩形
提取实际可取走的余料（已扣除零件占位与锯缝，区域互不重叠），按可配置的
最小长度 / 最小宽度筛选，展示来源板号、坐标、尺寸与面积；勾选清单项可
**一键追加到表单的临时余板库存**用于下一次排料，编号自动避让、不重复追加。
需要连续评估多批生产时，还可把当前表单**依次保存为多批**（订单与板材参数快照，
保存后修改表单不影响已保存批次）做**连续批次用料预演**：首批的表单余板作为初始库存，
按保存顺序逐批调用同一套排料规则——每批从余板池扣除已用编号、保留未用余板，
再把本批符合回收尺寸的余料以「批次号 + 原余料编号」入池供后续批次使用
（跨批编号不冲突）；逐批给出新开标准板数、已用与新增余板、批末库存与累计材料费，
某批无法加工时指出批次并停止，不提交部分结果；预演不改动表单与单次排料结果。
方案生成后还可做**机台开料排程**：输入 2～3 台机台（唯一名称、最大单刀长度、
切割速度与每板准备秒数），系统在机台间分配整板加工——每板不可拆分，
实际最长刀超过机台上限的板不能分配给该机台；单板耗时 = 每板准备秒数 +
该板全部刀长之和 ÷ 切割速度，同一机台按板号顺序连续加工；遍历全部可行分配，
取全部板完成时间最小者（平局按板号对应的机台输入序号字典序选取），
页面给出逐板机台、起止秒数与总完工秒数，原排料结果不变。
机台排程旁还可做**分时电费核算**：填写每台机台的**运行功率（千瓦）**与**开工时刻（HH:mm）**，
并配置一天内的**电价时段**（起止时分、元 / 千瓦时），时段须无重叠且完整覆盖 00:00～24:00、
功率与电价为非负数字（配置错误会指出原因）。核算沿用生成方案时的输入快照与现有机台参数
重算同一排程，把每板起止秒数叠加开工时刻换算为**实际时刻**；跨电价边界或午夜时按日循环拆分，
分段费用 = 功率 × 加工秒数 ÷ 3600 × 电价，**每板金额四舍五入到分后再汇总**。
页面列出逐板用电量与电费（含分段明细）、逐机台电费与总电费；修改功率、开工时刻或电价时段
即可重新核算，**不改变原排料与排程**。
每张板的裁切图旁还有**刀路执行记录**：排料时系统用未舍入几何按现有刀序**回放矩形切分**
（扣除实际锯缝带），记录每刀所切矩形的**产生刀**为其直接前置（初始整板无前置）；
仅当前置刀已完成才可标记该刀完成，不同分支可交错执行，重复标记不计数，
越序操作会提示缺少的前置刀；撤销一刀时同时撤销其已完成的所有后继刀，
保留其他分支状态。图上以颜色区分**已完成 / 可执行 / 被阻塞**的刀，
并显示每板完成刀数。记录仅存当前页面并绑定生成方案——修改表单不影响记录，
重新生成方案即清空；零锯缝、余板尺寸与无刀板均适用，落位、分摊与排程不受影响。

- 前端：React 18 + Vite
- 后端：Node.js + Express（排料 / 分摊 / 补切算法见 `server/src/cutting.js`）
- 部署：Docker / Docker Compose（镜像内完成依赖安装与前端构建，一键启动）

## 一条命令启动

```bash
docker compose up -d --build
```

该命令会自动完成：安装 npm 依赖 → 构建 React 静态资源 → 启动 Node 服务。

启动后访问：

> **http://localhost:8080**

停止服务：`docker compose down`

## 必要配置

| 配置项 | 说明 | 默认值 |
| --- | --- | --- |
| `PORT` | 宿主机暴露端口（在项目根目录 `.env` 中设置，可由 `.env.example` 复制） | `8080` |

容器内服务固定监听 8080 端口；如需改用 9090，可在 `.env` 中写 `PORT=9090`，
然后访问 http://localhost:9090 。

无需数据库或其他外部依赖；板价、订单等参数均随每次请求提交。

## 本地开发（不使用 Docker）

要求 Node.js ≥ 18。根目录一条命令安装所有 workspace 依赖：

```bash
npm install
```

分别启动后端（8080）与前端开发服务器（5173，已配置 `/api` 代理）：

```bash
npm run dev:server    # 终端 1
npm run dev:client    # 终端 2
```

访问 http://localhost:5173 。

生产方式本地运行（先构建再由 Express 托管）：

```bash
npm run build
npm start             # http://localhost:8080
```

算法自检（面积守恒、刀路几何、多订单归属、最大余数法分摊、刀路前置回放与执行记录等）：

```bash
npm test
```

## 使用说明

1. 填写**原板长度、原板宽度、锯缝宽度**以及**每张原板材料价（元）**
   （非负、最多两位小数，可为 0；单位统一即可，长度通常用 mm）。
   **设备最大单刀长度**为选填：留空表示设备不限制单刀长度、沿用全部既有排料规则；
   填写时必须为**正数**（与长度同单位），系统只产出每一刀都不超过该长度的刀路。
   **余料回收最小长度 / 最小宽度**为选填：留空表示不筛选、列出全部空闲余料；
   填写时必须为**非负数字**，用于方案生成后筛选可回收余料清单。
2. 在订单清单中为每张订单填写：
   - **唯一订单号**（留空则按“订单1、订单2…”自动编号，订单号不可重复）；
   - 零件行：名称、长度、宽度、数量；**同一订单内零件名不可重复**，
     **不同订单允许使用同名零件**（系统按“订单号 + 零件名”区分）。
   - 可添加 / 删除零件行与订单，或点击「载入示例」。
3. （选填）在**临时余板库存**中登记本次可动用的余板：
   - 每块余板填写**唯一编号**（如 `YB-01`，编号不可重复）与实际**长度、宽度**
     （均必须为正数，单位与原板一致），可添加 / 删除任意行（整行留空会被忽略）；
   - 排料时零件仍按原顺序：先在**所有已开板**（含先前启用的余板）的可用矩形中找落位，
     找不到才**按输入顺序**尝试尚未使用、且存在可行切法的余板，仍无可行余板时才开标准新板；
   - 余板与标准新板遵守完全相同的**锯缝、旋转 90° 与最大单刀长度**规则，
     板图按各板**实际尺寸**绘制。
4. 点击「生成多订单裁切方案」。结果区显示：
   - **用板总数**（余板数 + 新增标准板数）、**新增标准板数**、零件总数、零件总面积、
     **锯缝损耗面积**、**余料总面积**、利用率、**材料费合计（只计新增标准板）**，
     以及本次计算所用的**设备最大单刀长度上限**（未填写时显示“不限制”）；
   - **临时余板库存耗用**：列出每块余板的**已用 / 未用**状态、编号、实际尺寸与
     所在板号（已用按板号排序、未用按输入顺序排序）；
   - **可回收余料清单**：从每张板最终空闲矩形提取的可取走余料（来源板号、坐标、
     尺寸、面积），可勾选后一键追加到左侧临时余板库存（详见第 8 步）；
   - **分单取件清单**：按订单列出每个零件件号、**所在板号**与**坐标 (x,y)**，
     跨板订单以高亮徽标提示所在板号，供分单取件；
   - **订单材料费汇总**：各订单零件数、面积、所在板号与材料费分摊额；
   - 每张板的裁切图（按**实际板尺寸**等比绘制：米黄色为余料、彩色块为零件且
     **左上角标注订单号**、灰色锯缝带上的虚线为刀刃，圆形数字徽章即**下刀次序**），
     标题注明该板是**余板（含编号，不计材料费）**还是**新增标准板（含板价）**；
     标准板附本板材料费分摊表，所有板均附零件落位表（订单、坐标、尺寸、是否旋转）
     与刀路表（方向、起终点、贯穿长度）；设置了单刀上限时，板图下方统计还会给出
     **该板实际最长刀长 / 上限**；
   - 每张板裁切图旁的**刀路执行记录**：逐刀标记完成 / 撤销（详见第 12 步），
     图上按状态着色并显示该板完成刀数。
5. 若零件旋转后仍大于标准原板、且放不进任何余板，或订单号 / 余板编号重复、板价非法，
   页面会明确报错。
   设置了最大单刀长度时，若某零件在**所有现有板**上都找不到刀长不超限的落位，
   系统会依次尝试**尚未使用的余板**与**新的标准板**；全部候选仍都超限时，会报错指出
   **订单、零件名与件号**（并附标准板与各未用余板上两种切法所需刀长供判断），
   且**不会输出任何超限刀路**。
6. **缺件补切**：在「分单取件清单」的「补切」列勾选损坏件
   （按**订单号 + 零件名 + 件号**三元身份区分，跨订单同名零件互不影响），
   点击「生成补切方案」。系统以**当前排料输入（含余板库存）**重新计算原方案并校验所选件
   存在且无重复，然后仅将所选件按**原始尺寸**与**原输入顺序**合并重排为
   独立补切方案——**补切只开标准新板、不重复耗用余板库存**，
   **原方案落位与材料费分摊保持不变**。结果区展示：
   - 补切件数、**新增板数**、**新增材料费**（新增板数 × 单板价）；
   - **补切清单**：逐件关联**原板号 → 新板号**，含坐标、尺寸与是否旋转；
   - 补切材料费按订单分摊表（规则同原方案）；
   - 每张补切新板的裁切板图（含**下刀次序**）与落位 / 刀路明细表。
   补切沿用表单中的**设备最大单刀长度**（留空即不限制）；补切新板也无法在
   上限内加工时，同样报错指出订单、零件与件号，不输出超限刀路。
7. **撤单影响预览**：方案生成后，在结果区底部「撤单影响预览」中选择一张订单，
   点击「预览撤单影响」。系统以**生成该方案时的输入快照**分别计算撤单前、
   撤单后两套排料（之后修改表单不影响预览；**原方案与表单保持不变**），展示：
   - 撤单前后**新增标准板数**、**已用余板编号**、**材料费总额**及其差值；
   - 每张**保留订单**的分摊额（撤单前 / 撤单后）与**增减差值**
     （差值 = 撤单后 − 撤单前，费用差值按整数分计算）；
   - 被撤订单的撤单前分摊额与用板总数变化。
   订单号空白的订单已按**原输入位置**固定自动编号（订单1、订单2…），
   按该编号选择即可；撤单后其余订单**保持原名、不重新编号**。
   方案只有一张订单或订单号无效时，页面会明确报错。
8. **可回收余料清单**：方案生成后自动列出每张板最终空闲矩形中实际可取走的余料
   （已扣除零件占位与锯缝，区域互不重叠），按表单中的**余料回收最小长度 / 最小宽度**
   筛选（允许旋转 90° 匹配；留空则不筛选）。清单逐项展示**编号、来源板号、
   坐标、尺寸与面积**，编号规则为 `B来源板号-R区域序号`。勾选清单项后点击
   「追加选中余料到临时余板库存」，所选余料即以实际尺寸追加到左侧
   **临时余板库存**表单（行内标记"新追加"），**下一次生成方案时自动参与排料**；
   编号与现有余板重复时自动追加 `-2`、`-3`… 后缀避让，**同一方案重复操作不会
   重复追加**；当前方案的落位与材料费分摊保持不变。
9. **连续批次用料预演**：在左侧表单底部点击「保存当前表单为第 N 批」，把当前
   **订单清单与板材参数**（含临时余板库存）快照保存为一个批次，可依次保存多批
   （保存后修改表单不影响已保存批次；可单独删除某批或一键清空）。点击
   「开始连续预演」后按**保存顺序**逐批排料：
   - **首批的表单余板作为初始库存**，之后各批统一从上一批留下的余板池取料
     （各批保存时表单里的余板不再单独入池）；
   - 每批从余板池**扣除已用编号、保留未用余板**，再把本批**符合回收尺寸**的余料
     以 **`P批次号-原余料编号`** 入池供后续批次使用（与历史编号冲突时自动加后缀
     避让，**跨批编号不冲突**）；
   - 逐批展示**新开标准板数、已用与新增余板、批末库存与累计材料费**
     （材料费只计新开标准板，逐批累加）；
   - 某批无法加工时**指出批次并停止预演，不提交部分结果**；
   - 预演为只读评估：**不改动表单与单次排料结果**。
10. **机台开料排程**：方案生成后，在结果区底部「机台开料排程」中填写
    **2～3 台机台**（可添加 / 删除行，至少 2 台、至多 3 台）：
    - 每台机台填写**唯一名称**（去空白后非空、不可重复）、**最大单刀长度**与
      **切割速度**（长度 / 秒，均为正数）、**每板准备秒数**（非负数字）；
    - 点击「计算机台开料排程」，系统以**生成方案时的输入快照**重算同一方案后排程
      （**原排料结果不变**），仅接受**不超过 8 张板**的方案，超出时明确报错；
    - 结果区展示：总完工时间（全部板完成）、**逐板排程表**（板号 → 机台、
      刀长合计、实际最长刀、单板耗时与**起止秒数**）与**机台完工汇总**
      （各机台分得的板号队列与完工秒数）；
    - 每板不可拆分：板的**实际最长刀**超过某机台最大单刀长度时不能分配给该机台；
      某板在全部机台上都超限时明确报错并**指出板号**。
11. **分时电费核算**：在「机台开料排程」区块同一机台表中继续填写
    **运行功率（千瓦）**与**开工时刻（HH:mm，00:00～23:59）**，并在下方
    **电价时段**表中配置一天内的分时电价（可添加 / 删除时段行，至少 1 段、至多 48 段）：
    - 每段填写**开始时刻、结束时刻**（均为 HH:mm，结束允许 **24:00** 表示一日之末；
      不接受跨午夜写法，午夜用两段 24:00 / 00:00 相接表达）与**电价（元 / 千瓦时）**；
    - **功率与电价必须是非负数字**（功率 / 电价可以为 0）；各时段按开始时刻排序后必须
      **无重叠、无空档、完整覆盖 00:00～24:00**，配置错误时逐条指出原因（未从 00:00 开始、
      未覆盖到 24:00、在某时刻重叠、某两段间有空档、价格为负、时刻非法等）；
    - 点击「按分时电价核算电费」，系统以**生成方案时的输入快照与当前机台参数**重算同一排程
      （**原排料与已算出的排程不变**），同样仅接受**不超过 8 张板**的方案；
    - 结果区展示：总用电量与**总电费**、**逐板表**（机台、由起止秒数叠加开工时刻得到的
      **实际起止时刻**、加工秒数、用电量度、电费元、**分段明细**）与**逐机台汇总**
      （功率、开工时刻、加工板号、完工时刻、用电量、电费）；
    - 每板区间**跨电价边界或午夜时自动拆分**，午夜后电价**按日循环**回到第一段；
      分段费用 = 功率 × 分段秒数 ÷ 3600 × 该段电价，**每板费用四舍五入到分（整数分）**，
      逐板分汇总得到逐机台与总电费（合计严格守恒）；跨日时刻以「次日 / 第 N 日」标注，
      分段结束点恰在午夜时显示为当日 `24:00:00`；
    - **修改运行功率、开工时刻或电价时段后直接重新核算即可**：机台名称 / 单刀上限 /
      切割速度 / 准备秒数不变时排程不变，只重新计价；这些排程参数一旦修改，则需重新排程。
12. **刀路执行记录**：方案生成后，每张板裁切图旁的「刀路执行记录」面板按刀序列出
    每刀的**方向、贯穿长度与直接前置**（产生所切矩形的那一刀；「整板」表示无前置），
    面板顶部与板图下方统计均显示**该板已完成刀数（已完成 X / N 刀）**：
    - 每刀状态分三档：**已完成**（绿色）、**可执行**（蓝色，前置刀已完成或所切为整板）、
      **被阻塞**（灰色，前置刀未完成）；裁切图上的刀刃线与刀序徽章同步按状态着色；
    - 点击「标记完成」：仅当**直接前置刀已完成**（或该刀切的是初始整板）时才生效，
      **不同分支可交错执行**（不必按刀序依次操作）；**重复标记不计数**；
      越序操作时面板提示**缺少的前置刀**（如「请先完成第 2 刀」）；
    - 点击「撤销」：撤销该刀，并**同时撤销其已完成的所有后继刀**（沿前置关系向下传递），
      其他分支的完成状态保持不变；
    - 记录**仅存当前页面**并绑定当前生成方案：**修改表单不影响记录**，
      **重新生成方案即清空**；零锯缝、余板尺寸与无刀板（无刀板显示"无需执行"）均适用，
      落位、材料费分摊与机台排程不受影响。

## 切割规则

- 零件**严格按“订单输入顺序 → 订单内零件行顺序 → 数量 N 连续 N 件”**排料，
  不做大小重排；排料过程中不同订单的零件可共用同一张板（拼版）。
- 每件零件允许旋转 90°；余量相同时优先不旋转。
- 每件零件先在**所有已开板材**（含先前已启用的余板）中寻找可行落位；
  已开板都放不下时，先按余板的**输入顺序**尝试尚未使用、且能加工的余板，
  仍无可行余板时才开启标准新板，尽量减少新增标准板数。
- 每件零件落入某个当前可用矩形区域的左上角，需要两刀释放：
  - **竖切优先方案**：先竖切（贯穿该区域全高），再在左侧料块上横切；
  - **横切优先方案**：先横切（贯穿该区域全宽），再在上侧料块上竖切；
  - 自动选择锯缝损耗更小的方案，平局取竖切。
- 每一刀都**贯穿当前所在矩形区域**，锯缝宽度从余料一侧扣除并计入损耗；
  沿板边的修整切若余边不足一条完整锯缝，则按实际余边宽度落刀。
- 零件在某方向恰好占满区域时，该方向不再下刀。
- 余料面积 = 该板总面积 − 零件面积 − 锯缝损耗面积。

### 可回收余料清单（可选 `minOffcutLength` / `minOffcutWidth`）

- 排料结束后，系统从每张板**最终的空闲矩形**提取实际可取走的余料：
  空闲矩形已**扣除零件占位与锯缝带**，彼此**互不重叠**，
  未筛选时清单面积之和严格等于该板余料面积。
- `minOffcutLength` / `minOffcutWidth` 为可配置的最小回收尺寸：
  **留空 / 不传 / 传 0 均表示不筛选**；填写时必须为**非负数字**。
  余料按当前朝向**或旋转 90° 后**满足 长 ≥ 最小长度 且 宽 ≥ 最小宽度
  即视为可回收（与余板库存允许旋转使用的规则一致）。
- 清单逐项给出：**编号、来源板号、区域序号、坐标 (x,y)、尺寸 长×宽、面积**；
  编号规则为 `B{来源板号}-R{区域序号}`，区域序号为该板最终空闲区域的顺序号
  （从 1 起），未通过筛选的区域保留序号但不进入清单，
  因此同一区域在不同筛选条件下编号稳定。
- 清单只是对排料结果的**只读提取**：当前方案的落位、用板数与材料费分摊
  不受影响；`/api/recut` 重算的原方案同样携带该清单。
- 前端可将勾选项**一键追加到临时余板库存**（以实际尺寸入库，编号冲突自动
  加后缀避让，同一方案不重复追加），用于下一次排料。

### 临时余板库存（可选 `stockBoards`）

- 请求中传 `stockBoards: [{ id, width, height }]`（前端对应「临时余板库存」表格）：
  - `id`：必填的唯一编号（去空白后非空、全表不可重复）；
  - `width` / `height`：余板实际长 / 宽，均必须为**正数**（单位与标准原板一致）。
  省略、传 `null` 或空数组均表示本次不使用余板库存。
- 零件在所有**已开板**（含先前已启用的余板）的可用矩形中均无可行落位时：
  - 按 `stockBoards` 的**输入顺序**逐块尝试**尚未使用**的余板，在该余板整板范围内
    按与标准板相同的规则（不旋转优先、两种切法取锯缝损失更小者）寻找可行落位；
  - 取**第一块**几何上放得下、且切法满足锯缝 / 旋转 / 单刀长度限制的余板启用；
    放不下或切法超限的余板跳过、**保留为未用**；
  - 所有未用余板都不可行时，才开启一张标准新板。
- **每块余板最多使用一次**：启用后即从库存中消耗（同一块余板的后续可用矩形仍会继续
  接纳后续零件，但不会被“第二次开启”）；未被启用的余板原样在结果中列出。
- 余板可以比标准原板更大或更小；零件旋转后既放不进标准原板、也放不进任何余板时才报错。
- 板图与统计按每块板的**实际尺寸**绘制 / 汇总（总面积、余料面积、利用率均按实际板尺寸）。
- **材料费只对新增标准新板收取**：余板板价视为 0，其 `cost.priceCents = 0`、
  各订单在该板的分摊额均为 0；材料费合计 = 新增标准板数 × 单板价。
- 取件清单、订单汇总中的「所在板号」仍按开料顺序连续编号（余板与标准板统一编号），
  结果以 `boards[].kind`（`stock` / `standard`）与 `boards[].stockId` 区分。
- 缺件补切（`/api/recut`）**不使用余板库存**：补切排料一律开启标准新板，
  不重复消耗库存；请求体中仍可带 `stockBoards`，仅用于重算原方案。

### 设备最大单刀长度（选填 `maxCutLength`）

- **留空 / 不传 / 传 `null`**：不限制单刀长度，完全沿用上述排料与评分规则。
- 填写时必须为**正数**；长度单位与原板一致（通常 mm）。
- 对零件的每个候选落位（每张已开板的每个可用矩形区域；已开板均不可行时再依次尝试
  未用余板与标准新板）与每个朝向（不旋转 / 旋转 90°），系统分别构造：
  - **竖切优先**切法：记录其中每一刀的实际刀长（竖切刀长 = 贯穿区域高度，
    横切刀长 = 该刀锯缝带宽度）；
  - **横切优先**切法：同理记录每一刀实际刀长（横切刀长 = 贯穿区域宽度）。
- **仅当一种切法中所有刀长均 ≤ 上限时，该切法才可行**；系统只在可行切法之间做选择：
  - 同一落位 + 朝向下两种切法都可行时，沿用现有规则——锯缝损耗更小（余料面积更大）
    的优先，平局取竖切；
  - 落位与朝向之间仍按现有评分（最紧凑区域 → 余料损失最小 → 靠上 → 靠左 →
    已开板优先 → 不旋转）选取。
- 现有板上没有任何可行落位时，先按输入顺序尝试**未用余板**，仍不可行再按原规则
  **开启标准新板**；
  若所有候选（含未用余板）上两种切法、两种朝向也都超限（或零件旋转后仍大于所有板材），
  则整体报错并指出**订单、零件名与件号**（错误信息附标准板及各未用余板上各朝向 / 切法
  所需刀长），**不输出任何含超限刀的方案**。

## 缺件补切规则

- 损坏件以**订单号 + 零件名 + 件号**三元身份标识；不同订单的同名零件是不同件。
- 提交补切时，后端以**当前排料输入**重新计算原方案，并校验所选件
  **存在**（订单、零件名、件号均能对上）且**无重复**；任一不满足即整体报错。
- 仅所选件参与补切：按**原始尺寸**（未旋转的输入长 × 宽）与
  **原输入顺序**（订单 → 零件行 → 件号）合并，重排为**独立补切方案**；
  **补切只开标准新板，不使用、不消耗余板库存**（请求中的 `stockBoards` 仅用于重算原方案）；
  排料、旋转、锯缝与刀序规则与原方案一致；若提交了 `maxCutLength`，
  补切排料同样只选用全部刀长不超过该上限的切法，新板仍无法加工时按同样格式报错。
- 原方案的落位、用板数与材料费分摊**不受补切影响**，原样返回。
- 补切新板按同样的单板价计费：新增材料费 = 新增板数 × 单板价，
  并在补切方案内按订单零件面积比例分摊（最大余数法）。
- 补切清单逐件给出：**原板号**（原方案所在板）与**新板号**（补切方案所在板）。

## 撤单影响预览规则

- 撤单对象以**订单号**定位：订单号空白的订单先按**原输入位置**固定自动编号
  （订单1、订单2…），再按编号匹配；订单号不在方案中即报错并列出可选订单号。
- 方案**只有一张订单**时不允许撤单预览（撤单后至少应保留一张订单），明确报错。
- 以生成方案时的**同一份输入快照**分别计算撤单前、撤单后两套排料：
  撤单后方案 = 从订单清单中筛除该订单后重算，**其余订单保持原名、不重新编号**，
  排料、旋转、锯缝、余板库存与单刀上限规则与 `/api/cut` 完全一致；
  原方案落位、用板数与材料费分摊**不受撤单预览影响**。
- 输出对比（差值 = 撤单后 − 撤单前）：
  - **新增标准板数**、**已用余板编号**（含新增启用 / 不再使用的余板编号）、
    **材料费总额**（只计新增标准板）；
  - 每张**保留订单**的分摊额（前 / 后）与**增减差值**，费用差值一律按**整数分**计算；
  - 被撤订单的撤单前分摊额。

## 连续批次用料预演规则

- 每个批次是保存时表单的完整快照（订单清单、原板参数、锯缝、板价、单刀上限、
  余料回收尺寸与临时余板库存）；**保存后修改表单不影响已保存批次**。
- **首批**快照中的临时余板库存作为整个预演的**初始余板池**；后续各批快照自带的
  余板库存不再入池，统一从上一批留下的余板池按输入顺序取料。
- 按批次保存顺序逐批调用与 `/api/cut` 完全相同的排料规则（含锯缝、旋转、
  单刀上限与该批的余料回收尺寸筛选）。
- 每批结束后更新余板池：
  - 从池中**扣除本批已用余板编号**，未用余板原样保留；
  - 本批**符合回收尺寸的余料**（即该批 `offcuts` 清单）逐项以
    **`P{批次号}-{原余料编号}`** 入池（如第 1 批的 `B2-R3` → `P1-B2-R3`），
    供后续批次使用；与初始库存或已生成编号冲突时自动追加 `-2`、`-3`… 后缀，
    **全程编号不重复**。
- 逐批输出：新开标准板数、已用余板（含所在板号）、新增入池余板（含来源余料编号）、
  批末库存（区分初始库存与各批回收）与累计材料费（只计新开标准板，逐批累加）。
- 任一批次无法加工（零件放不下、刀长超限或输入非法）时，报错**指出批次号**并
  停止预演，**不返回任何批次结果**；预演为只读计算，不改动各批输入快照，
  也不改动表单与单次排料结果。

## 机台开料排程规则

- 以**生成方案时的输入快照**重算裁切方案（与 `/api/cut` 完全相同的排料规则），
  排程为只读计算，**原排料结果不变**；仅接受**不超过 8 张板**的方案，超出时明确报错。
- 机台清单 `machines`：**2～3 台**，每台包含：
  - `name`：**唯一名称**（去空白后非空、全表不可重复）；
  - `maxCutLength`：最大单刀长度，必须为**正数**（与原板同单位）；
  - `speed`：切割速度（长度 / 秒），必须为**正数**；
  - `setupSeconds`：每板准备秒数，必须为**非负数字**。
- **每板不可拆分**：板的**实际最长刀**（`boards[].longestCut`）超过某机台
  `maxCutLength` 时，该板不能分配给该机台；某板在全部机台上都超限时，
  明确报错并**指出板号**。
- **单板耗时** = 该机台每板准备秒数 + 该板全部刀长之和 ÷ 该机台切割速度；
  **同一机台按板号顺序连续加工**（无空转），机台完工时间 = 所分得各板耗时之和。
- **遍历全部可行分配**，取**全部板完成时间**（各机台完工时间的最大值）最小者；
  平局按**板号对应的机台输入序号**序列的**字典序**选取。
- 输出逐板机台（名称与输入序号）、刀长合计、实际最长刀、单板耗时与**起止秒数**，
  以及各机台分得的板号队列、完工秒数与**总完工秒数**（秒数保留 3 位小数）。

## 分时电费核算规则

- 以**生成方案时的输入快照**与当前机台参数（含运行功率、开工时刻）重算与 `/api/schedule`
  **完全相同的排程**：机台分配、单板耗时、起止秒数均一致；核算为只读计算，
  **原排料结果与已算出的排程不变**；同样仅接受**不超过 8 张板**的方案。
- 机台清单除排程四参数外，另需：
  - `power`：**运行功率（千瓦 kW）**，必须为**非负数字**（可为 0，此时用电量与电费均为 0）；
  - `startTime`：**开工时刻**，`HH:mm` 格式（允许省略小时前导 0，如 `8:05`），
    合法范围 **00:00～23:59**；不接受 24:00（24:00 仅可作为电价时段结束时刻）。
- 一天内的电价时段 `tariffs: [{ start, end, price }]`：
  - 至少 1 段、最多 48 段；`start` 为 00:00～23:59 的 HH:mm，`end` 为 00:00～24:00 的 HH:mm
    （**`24:00` 仅可作为结束时刻**，表示一日之末）；每段必须 `start < end`
    （同日时刻，不接受跨午夜写法——午夜用相邻两段首尾相接表达）；
  - `price` 为**电价（元 / 千瓦时，即元 / 度）**，必须为**非负数字**，可为 0；
  - 各时段按开始时刻排序后必须**无重叠、无空档**：第一段自 **00:00** 开始、
    最后一段到 **24:00** 结束、相邻段首尾时刻相等，**完整覆盖一整天**；
    输入顺序可乱，后端按开始时刻排序。
- **实际时刻换算**：每板的相对起止秒数叠加该机台开工时刻（自当日 00:00 起的分钟数 × 60）
  得到实际时钟；输出 `HH:mm:ss`（含最多 3 位小数秒），并标注相对开工当日的天序号
  （0 = 当日、1 = 次日、其余为「第 N 日」）；分段结束点恰为午夜时显示为当日 `24:00:00`。
- **分段规则**：板的加工区间每跨越一个电价边界或午夜就拆分一段；午夜后电价**按日循环**
  （即超过 24:00 的工时循环回 00:00 起的第一段电价），可正确处理跨多日的长时间加工。
- **计价公式**：分段用电量（度 / kWh）= 功率 × 分段加工秒数 ÷ 3600；
  **分段费用（元）= 功率 × 加工秒数 ÷ 3600 × 该段电价**；
  **每板费用 = 其各分段费用之和四舍五入到整数分**（按分四舍五入，与材料费口径一致）。
- **汇总守恒**：逐机台电费 / 总电费均由**逐板整数分**累加，因此
  各板电费之和 **严格等于** 逐机台电费之和 **严格等于** 总电费；
  用电量（kWh，保留 6 位小数）按分段 / 逐板 / 逐机台 / 总量逐级汇总展示。
- 修改 `power` / `startTime` / `tariffs` 等**计价参数**只影响电费核算结果；
  机台名称、最大单刀长度、切割速度、每板准备秒数或排料输入变化后排程才会改变。
- 机台排程与电价时段的全部既有校验仍然适用：机台不是 2～3 台、名称缺失 / 重复、
  上限或速度非正、准备秒数为负、功率为负、开工时刻非法、电价时段缺失 / 重叠 / 有空档 /
  未覆盖全天、电价为负，或方案超过 8 张板、某板无可行机台时，均返回 HTTP 400 并指出原因。

## 刀路执行前置规则

- 排料结束后，对每张板用**未舍入几何**按现有刀序**回放矩形切分**：
  初始为整板矩形（无产生刀）；每刀在其当前所在矩形内贯穿，从该矩形中
  **扣除实际锯缝带**（边修刀缝带可能窄于标准锯缝、零锯缝时缝带宽度为 0），
  剩余矩形记为由该刀产生，供后续刀查找所属。
- 每刀的**直接前置** = 所切矩形的产生刀；所切为初始整板时无前置
  （API 中 `boards[].cuts[].pred`，0 表示无前置，否则为前置刀序）。
- 执行记录（仅存当前页面、绑定当前生成方案）：
  - 仅当**直接前置刀已完成**（或无前置）时才可标记该刀完成；
    不同分支（前置相同或无关的刀）**可交错执行**，不必按刀序；
  - **重复标记不计数**；越序操作时界面提示**缺少的前置刀**；
  - **撤销一刀时同时撤销其已完成的所有后继刀**（沿前置关系向下传递），
    其他分支的完成状态保持不变；
  - 裁切图上以颜色区分**已完成 / 可执行 / 被阻塞**的刀，并显示每板完成刀数。
- **修改表单不影响记录；重新生成方案即清空记录**；零锯缝、余板尺寸与
  无刀板均适用；该功能为只读回放 + 页面本地状态，**不改落位、分摊或排程**。

## 材料费分摊规则

- 每张**新增标准开料板**按固定的**单板材料价**计费；板价非负、最多两位小数，
  内部统一换算成整数“分”。**临时余板库存板不收费**（板价 0，不分摊）。
- 每张标准板内部，按**各订单在该板上的零件实际面积占比**分摊该板板价：
  先取各份额的整数分（向下取整），剩余尾差用
  **最大余数法（Hamilton / Largest Remainder）**逐分补入余数最大的订单；
  **余数相同时按订单输入顺序**优先。
- 因此保证：
  - 每板各订单分摊额之和 **严格等于该板板价**（余板为 0）；
  - 各订单跨板汇总之和 **严格等于总材料价（新增标准板数 × 单板价）**。
- 板上没有任何零件落位的订单不参与该板分摊；板价为 0 时各订单分摊 0 元。

`POST /api/cut`（多订单拼版）

```json
{
  "boardWidth": 2440,
  "boardHeight": 1220,
  "kerf": 3,
  "boardPrice": 180.00,
  "maxCutLength": 800,
  "minOffcutLength": 200,
  "minOffcutWidth": 150,
  "stockBoards": [
    { "id": "YB-01", "width": 1200, "height": 800 },
    { "id": "YB-02", "width": 320, "height": 150 }
  ],
  "orders": [
    {
      "orderNo": "SO-1001",
      "parts": [
        { "name": "柜门", "width": 600, "height": 400, "quantity": 8 }
      ]
    },
    {
      "orderNo": "SO-1002",
      "parts": [
        { "name": "柜门", "width": 600, "height": 400, "quantity": 4 }

    }

```

- `stockBoards`（可选）：本次临时余板库存，按输入顺序尝试。每项：
  - `id`：余板唯一编号（字符串，去空白后非空、全表不可重复）；
  - `width` / `height`：余板实际长 / 宽，均必须为**正数**。
  省略 / 传 `null` / 空数组均表示不使用余板。每块余板最多使用一次，
  启用时机晚于所有已开板、早于标准新板；余板不计材料费，补切不消耗余板。
- `maxCutLength`（可选）：设备最大单刀长度，必须为**正数**；省略、传 `null` 或
  空字符串均表示**不限制**。设置后只输出每刀刀长均不超过该值的方案，
  全部切法均超限时返回 HTTP 400，错误信息指出订单、零件与件号。
- `minOffcutLength` / `minOffcutWidth`（可选）：可回收余料清单的最小回收尺寸，
  必须为**非负数字**；省略、传 `null`、空字符串或 `0` 均表示**不筛选**、
  列出全部空闲余料。余料按当前朝向或旋转 90° 后满足尺寸要求即入列。

  输入序号与实际尺寸。每块余板最多出现一次已用记录。
- `minOffcutLength` / `minOffcutWidth`：本次实际使用的余料最小回收尺寸（未设置为 `0`）。
- `offcuts[]`：可回收余料清单，逐项含编号 `id`（`B来源板号-R区域序号`）、来源板号

- `boards[].cost.shares[]`：标准板上逐订单面积占比（`ratio` 百分比）与分摊额（分）。
- `maxCutLength`：本次计算实际使用的单刀上限；未设置时为 `null`。
- `boards[].longestCut`：该板所有刀路中的实际最长刀长（无刀时为 `0`），
  设置上限后必有 `longestCut ≤ maxCutLength`；`boards[].cuts[].length`
  仍为逐刀贯穿长度。
- `boards[].cuts[].pred`：该刀的**直接前置刀序**（回放矩形切分得到的所切矩形产生刀），
  `0` 表示所切为初始整板、无前置；供刀路执行记录标记 / 撤销使用，
  落位、分摊与排程不受影响。

旧版单订单请求（顶层 `parts`、无 `orders` 与 `boardPrice`）仍然兼容，
整体视为单个自动编号订单、板价 0。

成功返回 `{ "ok": true, "result": { ... } }`；零件无法放入标准原板且放不进任何余板、
所有切法均超过 `maxCutLength`，或输入非法（含余板编号缺失 / 重复、余板尺寸非正、
余料回收最小尺寸为负）时返回 HTTP 400 与 `{ "ok": false, "error": "..." }`。

```json
      { "id": "P1-B2-R3", "width": 600, "height": 397, "fromBatch": 1, "fromOffcut": "B2-R3" }
    ],
    "batches": [
      {
        "batch": 1,
        "boardWidth": 2440,
        "boardHeight": 1220,
        "boardPrice": 180,
        "ordersCount": 1,
        "totalParts": 8,
        "boardsCount": 2,
        "standardBoardsCount": 2,
        "materialCents": 36000,
        "cumulativeMaterialCents": 36000,
        "poolBeforeCount": 1,
        "stockUsed": [
          { "id": "YB-01", "inputIndex": 1, "board": 1, "width": 1200, "height": 800 }
        ],
        "stockAdded": [
          { "id": "P1-B2-R3", "fromOffcut": "B2-R3", "fromBoard": 2, "width": 600, "height": 397 }
        ],
        "poolAfter": [
          { "id": "P1-B2-R3", "width": 600, "height": 397, "fromBatch": 1, "fromOffcut": "B2-R3" }
        ]
      }
    ]
  }
}
```

- `batches[]`：逐批汇总（按保存顺序）。`standardBoardsCount` 为本批新开标准板数；
  `materialCents` / `cumulativeMaterialCents` 为本批材料费与逐批累计材料费（整数分，
  只计新开标准板）；`poolBeforeCount` 为批初库存块数。
- `stockUsed[]`：本批从余板池扣除的已用余板（编号、池内序号、所在板号与尺寸）；
  `stockAdded[]`：本批符合回收尺寸、以 `P{批次号}-{原余料编号}` 入池的余料
  （含来源余料编号 `fromOffcut` 与来源板号 `fromBoard`），供后续批次使用。
- `poolAfter[]`：批末库存（未用余板 + 本批新入池余料），初始库存不带 `fromBatch`，
  回收余板带 `fromBatch` / `fromOffcut` 标明来源批次与余料编号；全程编号不重复。
- `totalStandardBoards` / `totalMaterialCents`：全部批次的新开标准板总数与累计材料费；
  `finalPool`：全部批次结束后的最终余板库存。
- 任一批次无法加工时返回 HTTP 400 与 `{ "ok": false, "error": "第 N 批无法加工：…" }`，
  不返回任何批次结果；`batches` 缺失 / 为空 / 非数组时同样返回 HTTP 400。

`POST /api/schedule`（机台开料排程）

请求体 = 排料输入（同 `/api/cut`，通常为生成方案时的表单快照）+ `machines`
机台清单（2～3 台）。以该快照重算同一裁切方案后，在机台间分配整板加工，
**原排料结果不变**；方案超过 8 张板时返回 HTTP 400。

```json
{
  "boardWidth": 1200,
  "boardHeight": 800,
  "kerf": 0,
  "orders": [
    { "orderNo": "A", "parts": [{ "name": "块", "width": 600, "height": 400, "quantity": 9 }] }
  ],
  "machines": [
    { "name": "机台A", "maxCutLength": 800, "speed": 100, "setupSeconds": 0 },
    { "name": "机台B", "maxCutLength": 800, "speed": 200, "setupSeconds": 0 }
  ]
}
```

返回（节选）：

```json
{
  "ok": true,
  "result": {
    "boardsCount": 3,
    "makespan": 20,
    "machines": [
      { "index": 1, "name": "机台A", "maxCutLength": 800, "speed": 100,
        "setupSeconds": 0, "boards": [1], "end": 20 },
      { "index": 2, "name": "机台B", "maxCutLength": 800, "speed": 200,
        "setupSeconds": 0, "boards": [2, 3], "end": 17 }
    ],
    "boards": [
      { "board": 1, "machine": "机台A", "machineIndex": 1, "cutLength": 2000,
        "longestCut": 800, "duration": 20, "start": 0, "end": 20 },
      { "board": 2, "machine": "机台B", "machineIndex": 2, "cutLength": 2000,
        "longestCut": 800, "duration": 10, "start": 0, "end": 10 },
      { "board": 3, "machine": "机台B", "machineIndex": 2, "cutLength": 1400,
        "longestCut": 800, "duration": 7, "start": 10, "end": 17 }
    ]
  }
}
```

- `machines[]`：逐机台参数回显（`index` 为输入序号，从 1 起）、分得的板号队列
  `boards`（按板号顺序连续加工）与完工秒数 `end`（未分板的机台为 `[]` 与 `0`）。
- `boards[]`：逐板排程——`machine` / `machineIndex` 为分得的机台名称与输入序号，
  `cutLength` 为该板全部刀长之和，`longestCut` 为实际最长刀，`duration` 为单板耗时
  （每板准备秒数 + 刀长合计 ÷ 切割速度），`start` / `end` 为起止秒数；
  同一机台上相邻板的结束与开始秒数首尾相接。
- `makespan`：全部板完成时间（各机台完工秒数的最大值），遍历全部可行分配取得最小值，
  平局按板号对应的机台输入序号字典序选取；秒数均保留 3 位小数。
- 方案超过 8 张板、某板在全部机台上都超单刀上限（错误信息指出板号）、机台不是
  2～3 台、名称缺失 / 重复、上限或速度非正、准备秒数为负时，返回 HTTP 400 与
  `{ "ok": false, "error": "..." }`。

`POST /api/electricity`（分时电费核算）

请求体 = 排料输入（同 `/api/cut`，通常为生成方案时的表单快照）+ `machines` 机台清单
（在排程四参数外另带 `power` 运行功率 kW 与 `startTime` 开工时刻 HH:mm）
+ `tariffs` 一天内电价时段（无重叠、完整覆盖 00:00～24:00）。
后端重算与 `/api/schedule` 完全相同的排程（**原排料与排程不变**），把每板起止秒数
叠加机台开工时刻换算为实际时刻，跨电价边界 / 午夜按日循环拆分后逐段计费，
每板费用四舍五入到分再汇总。

```json
{
  "boardWidth": 1200,
  "boardHeight": 800,
  "kerf": 0,
  "orders": [
    { "orderNo": "A", "parts": [{ "name": "块", "width": 600, "height": 400, "quantity": 13 }] }
  ],
  "machines": [
    { "name": "机台A", "maxCutLength": 800, "speed": 50, "setupSeconds": 0,
      "power": 10, "startTime": "00:00" },
    { "name": "机台B", "maxCutLength": 800, "speed": 50, "setupSeconds": 0,
      "power": 10, "startTime": "23:59" }
  ],
  "tariffs": [
    { "start": "00:00", "end": "08:00", "price": 0.3 },
    { "start": "08:00", "end": "24:00", "price": 1.0 }
  ]
}
```

返回（节选）：

```json
{
  "ok": true,
  "result": {
    "boardsCount": 4,
    "makespan": 80,
    "tariffs": [
      { "start": "00:00", "end": "08:00", "price": 0.3 },
      { "start": "08:00", "end": "24:00", "price": 1 }
    ],
    "totalKwh": 0.411111,
    "totalCents": 23,
    "schedule": { "...": "与 POST /api/schedule 返回完全相同的排程结果" },
    "machines": [
      { "index": 1, "name": "机台A", "power": 10, "startTime": "00:00",
        "boards": [1, 2], "end": 80, "finishDay": 0, "finishTime": "00:01:20",
        "kwh": 0.222222, "costCents": 6 },
      { "index": 2, "name": "机台B", "power": 10, "startTime": "23:59",
        "boards": [3, 4], "end": 68, "finishDay": 1, "finishTime": "00:00:08",
        "kwh": 0.188889, "costCents": 17 }
    ],
    "boards": [
      { "board": 3, "machine": "机台B", "machineIndex": 2,
        "start": 0, "end": 40,
        "startDay": 0, "startTime": "23:59:00",
        "endDay": 0, "endTime": "23:59:40",

      { "board": 4, "machine": "机台B", "machineIndex": 2,

        "startDay": 0, "startTime": "23:59:40",
        "endDay": 1, "endTime": "00:00:08",

            "seconds": 8, "kwh": 0.022222, "priceRate": 0.3, "price": 0.0067 }

```

- `schedule`：与 `/api/schedule` 同构的完整排程结果（逐板机台、起止秒数、机台汇总），
  便于在同一响应中核对核算所用排程；分时核算不会修改该排程。
- `boards[]`：逐板核算——`start` / `end` 为相对开工的秒数；`startDay` / `startTime`、
  `endDay` / `endTime` 为叠加机台开工时刻后的实际时钟（`day` 0 = 当日、1 = 次日…）；
  `kwh` 为该板用电量（度，保留 6 位小数）；`costCents` 为该板电费（**整数分，已四舍五入**）。
- `boards[].segments[]`：跨电价边界 / 午夜拆分后的分段——起止实际时刻与天序号、
  `seconds`（秒，3 位小数）、`kwh`（分段用电量）、`priceRate`（该段电价元 / 度）与
  `price`（分段费用元，4 位小数，仅供展示；**入账以逐板整数分为准**）；
  午夜后电价按日循环，分段结束点恰在午夜时显示当日 `24:00:00`。
- `machines[]`：逐机台回显 `power` / `startTime`、加工板号队列、相对完工秒数 `end` 与
  实际完工时刻 `finishDay` / `finishTime`（未分板机台完成时刻回显其开工时刻、
  用电量与电费为 0）、`kwh` 与 `costCents`（由逐板整数分汇总）。
- `totalKwh` / `totalCents`：全部板用电量合计与**总电费（整数分）**；
  逐板电费之和 = 逐机台电费之和 = `totalCents`。
- `tariffs[]`：按开始时刻排序后的电价时段回显。
- 机台参数（含功率为负、开工时刻非法）、电价时段（缺失 / 非数组 / 空、起止时刻非法、
  结束不晚于开始、价格为负、未从 00:00 开始、未覆盖到 24:00、时段重叠或存在空档）、
  方案超过 8 张板或某板无可行机台时，返回 HTTP 400 与
  `{ "ok": false, "error": "..." }`，错误信息指出具体机台 / 时段编号与原因。
